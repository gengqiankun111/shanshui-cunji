## 3. 倒排端到端专项（K/J 项在 1 亿库的验证形态）
- 1 亿库配置倒排为空（inverted_fields=[]）。写入 100 万行带枚举字段（status/city，非排除字段）：
  - 写入 100 万行 15.6s = **64,117 rows/s**（批 2000，无回填 HotCache 干扰）
  - 倒排分页（mem posting 快速路径，窗口解码 + batch_get 回表）：
    - `WHERE status='active' LIMIT 10`（~33 万 posting）：**2.68ms**
    - `WHERE city='beijing' LIMIT 10 OFFSET 100`：**3.20ms**
    - 主键点查对照：0.25ms
- **说明**：mysql 协议无显式倒排 flush 入口（flush_inverted 为引擎 API）→ 大 posting 留在内存
  posting（mem 路径，search_paged 走 merge_distinct）；**v3 分块段格式 + 后台 GC 收敛**由单元
  测试（488 全绿：v3 分页与全量一致、跨段去重、GC worker 收敛段数）+ demo（posting-chunk
  x211/x4491、inverted-gc-bg 丢失更新研究）覆盖——1 亿库空倒排配置不触发段路径。

## 4. 结论
- **v0.8.0 1 亿库无回归**：单语句读写大幅提升、事务类持平、write_only 提升
- 倒排端到端可用（写入 → mem posting 分页 → 回表），延迟亚毫秒~毫秒级
- J/K 段格式与 GC 能力由单测 + demo 实测背书（v3 分块：近页 x211 / COUNT x4491；GC 后台：
  信号驱动收敛不阻塞查询）
