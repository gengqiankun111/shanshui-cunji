# SQL / MySQL 协议语法支持现状（cjserver 视角）

> 范围：经 MySQL wire（`cjserver`）暴露给 MySQL 客户端（mysql cli /
> pymysql / JDBC / rust mysql crate 等）的 SQL 语法与事务语义支持面，对照 **MySQL 8.0**。
> 与 [README §4](./README.md)、[feature.md](../feature.md)、
> [feature_remain.md](../feature_remain.md) 校准；本文按 **已支持 / 待开发 / 待决策** 三档组织。
> 数据来源标注：〔实测〕= RR 对拍/压测实证；〔定位〕= 源码定位；〔既有〕= 既有文档/测试。

---

## 一、已支持

### 1.1 连接层（实测：rust mysql crate v26 / 协议级测试通过）

| 能力 | 状态 | 备注 |
| --- | --- | --- |
| 握手 HandshakeV10 + `mysql_native_password` | ✅ | 空口令/口令均可 |
| CONNECT_ATTRS 消费 | ✅ | RustMySQL 等客户端随握手响应发 attrs，未消费会错读首条命令（已修） |
| `SELECT @@max_allowed_packet` | ✅ | rust mysql crate 建连必经查询；返回数值（已修） |
| 预处理语句 COM_STMT_*（PREPARE/EXECUTE/CLOSE） | ✅ | 〔既有〕 |
| SHOW DATABASES / TABLES / VARIABLES、`SELECT VERSION()` | ✅ | 〔既有〕 |

### 1.2 数据语句（实测：RR/压测通过部分）

| 语句 | 支持形态 | 备注 |
| --- | --- | --- |
| INSERT | 单行 / 多行 `VALUES (...),(...)` | ✅ 实测 |
| UPDATE / DELETE | **仅 `WHERE id = N` 单点** | `id IN (...)` 待开发（见 2.1） |
| SELECT 点查 | `WHERE id = N` | 事务内/外均可 |
| SELECT 范围 | `id BETWEEN A AND B`、`id IN (…)` | 事务外任意列 BETWEEN；**事务内仅主键**（见 2.1） |
| SELECT 聚合 | COUNT / SUM / AVG / MIN / MAX | COUNT/SUM 走倒排计数/统计载荷快路径 |
| SELECT 排序/分组 | ORDER BY 单/多字段、GROUP BY 单/多字段、HAVING、LIMIT/OFFSET | 〔既有〕 |
| 字段条件过滤 | `WHERE f = 'v'` / `f IN (...)` / `f BETWEEN`（非事务） | 倒排/下推 |

### 1.3 事务（实测：确定性 RR 场景 6 用例中 3 项通过）

| 能力 | 状态 | 备注 |
| --- | --- | --- |
| BEGIN / COMMIT / ROLLBACK | ✅ | COMMIT 持久化实测 PASS；ROLLBACK 丢弃实测 PASS |
| 会话隔离级别 | RC / RR / SERIALIZABLE；READ UNCOMMITTED 映射 RC | `SET [SESSION] TRANSACTION ISOLATION LEVEL` |
| 点读快照（RR） | ✅ 一致读两次同值；他事务 UPDATE/DELETE 提交不影响快照 | C1/C3 前 4 步实测 PASS |
| 事务内自写可见 | ✅ 自插/自更后立即读到新值 | C2 实测 PASS |
| 事务内范围读（BETWEEN，RR） | ⚠️ 快照不生效（幻读） | 见 2.1-B |

## 二、待开发（已确认缺口；2026-09-03 RR 对拍实证 + 源码定位）

| # | 缺口 | 现象（两库对拍） | 定位 |
| --- | --- | --- | --- |
| A | 事务内 `SELECT … FOR UPDATE` 不是当前读 | 他事务已把 val 0→1 提交，FOR UPDATE 仍返回快照旧值 0（C1）；他事务已 DELETE 提交，FOR UPDATE 仍返回旧行（C3）。MySQL 前者返回 1、后者返回 ∅ | `src/mysql.rs::txn_select` 无 FOR UPDATE 分支，点查一律 `txn_get`（快照）、范围一律 `scan_range_txn`（快照）。引擎已有最新读 `engine.get` / `engine.scan_range` 可用 |
| B | 事务内范围一致读（BETWEEN）出现幻读 | 他事务在快照后于区间内 INSERT 提交，主事务范围一致读仍返回该新行（C4）。MySQL 快照不见幻影 | `engine.scan_range_txn` → `column_family::scan_range_at`，memtable 层疑似未按 `seq <= snapshot` 过滤（对照点读 `get_bytes_at` 正常） |
| C | UPDATE / DELETE 不支持 `WHERE id IN (...)` | 报 `1064 update syntax: WHERE 缺 =`；随机矩阵批量写通道全废（已用工具 `--lite-writes` 收窄规避） | sqlish/update 解析仅等值点 |
| D | `DROP TABLE IF EXISTS` 不 purge 数据 | 反复 `--init` 后旧行残留累计（SCC 侧 2000 种子 → 累计 10000 行） | `mysql.rs` DDL 分支 DROP TABLE 直接返回 OK，未清表 |
| E | INSERT 主键重复不报 1062 | MySQL `Duplicate entry '…' for key PRIMARY`，SCC 返回 aff=1 成功（潜在覆盖语义） | 写路径无 PK 唯一性校验 |
| F | 事务内非主键列谓词不可用 | `WHERE a=… AND b=…` → `1064 事务内仅支持 WHERE id= / BETWEEN / IN` | `txn_select_by_predicate` 相关分支未接入/受限 |
| G | 无条件 `COUNT(*)` 慢 | key-only 全扫（~10× 级） | 〔既有〕feature_remain |
| H | 组结果 `ORDER BY 聚合列`、`HAVING` 无 GROUP BY | 未支持 | 〔既有〕README §4.2 |

## 三、待决策（不确定是否要支持 / 支持到什么程度）

| 项 | 现状 | 争议点 / 选项 |
| --- | --- | --- |
| 快照建立点 | SCC = **BEGIN 时**取快照（`txn_begin` 即 `begin_snapshot`）；MySQL = **首次一致读**时建立 | BEGIN 后、首读前若有他事务提交：MySQL 可见、SCC 不可见。是否对齐 MySQL（推迟到首读建快照）？或维持现状并在文档声明差异 |
| `FOR UPDATE` 的锁语义 | 当前读尚未实现（2.1-A）；SCC 无行锁模型，并发写冲突靠"快照后修改检测 + abort" | 只做"当前读=最新值"够不够？是否要 MySQL 式行锁 + 阻塞 + `1205 锁等待超时` 语义？（SERIALIZABLE 已有共享锁雏形） |
| 死锁/锁等待错误对齐 | 错误分类与 MySQL（1213/1205）不一致 | 对拍工具按文本识别，行为差异是否要收敛 |
| 二级唯一索引 / 多列唯一 | DDL 无 UNIQUE 约束；INSERT 重复不报错（2.1-E） | 是否立项唯一索引（影响 DUP 语义、`INSERT … ON DUPLICATE KEY UPDATE`） |
| ODKU（`INSERT … ON DUPLICATE KEY UPDATE`） | 不纳入（方案注明） | 是否后续支持（依赖唯一索引决策） |
| READ UNCOMMITTED | 映射 READ COMMITTED（无脏读，比真 RU 更严） | 是否实现真 RU |
| 多库语义（URL `/db`、CREATE/USE DATABASE） | 仅单一默认集合；多库语句忽略/放行 | 是否支持多"库"命名空间（影响工具/迁移隔离） |
| DROP TABLE 语义 | 不 purge（2.1-D） | 明确为"物理清表"或"仅删元数据+文档说明" |

## 附：确定性验证方法（对拍工具）

- `rr-conformance --rr-cases`：6 个确定性 RR 场景（快照稳定 / 自写可见 / 已删行在快照 /
  防幻读 / COMMIT 持久 / ROLLBACK 丢弃），每步 MySQL 与自研库同 SQL 顺序执行并互比 +
  校验 RR 期望（MySQL 为 oracle）。用例键 9000xx，自清理。
- 2026-09-03 基线：C2/C5/C6 PASS；**C1、C3、C4 FAIL**（即 2.1-A、2.1-B 两缺陷）；
  修复后预期 6/6 PASS。复验命令见 `rr-conformance/README.md`。
