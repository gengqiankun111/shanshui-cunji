# 启动数据库（cjserver）

## 快速开始

```bash
# 构建
sudo apt install rustup
rustup install nightly          # 安装最新的 nightly
cargo +nightly build --release  # 使用 nightly 编译

# 前台启动（占住终端，Ctrl+C 退出）
/home/gqkdb/shanshui-cunji/target/release/cjserver \
  --data-dir /home/gqkdb/scc-p144/db-b1-default \
  --bind 127.0.0.1:3308

# 或后台启动（推荐，测试用）
nohup /home/gqkdb/shanshui-cunji/target/release/cjserver \
  --data-dir /home/gqkdb/scc-p144/db-b1-default \
  --bind 127.0.0.1:3308 > /tmp/cjserver.log 2>&1 &
```

## 参数

| 参数 | 说明 | 缺省 |
| --- | --- | --- |
| `--data-dir <dir>` | 数据目录（必需） | — |
| `--bind <ip:port>` | MySQL 协议监听地址 | `0.0.0.0:3307` |
| `--config <toml>` | **仅运行参数**（缓存/组提交/看门狗等）；索引声明不从这里来 | 内置默认 |
| `--user / --password` | 登录账号 | root / 空 |
| `--watchdog-secs N` | 全扫/聚合看门狗放宽（大库） | 30 |
| `--async` | tokio 协程网络层 | 同步 |

## 索引声明随库（P131b 声明制）

索引声明**不是配置文件**，而是数据目录内的 `cj.schema.json`（按表声明倒排/位图/组合索引）。
启动时自动读取装配，无需 `--config`；**没有声明 = 零索引**（写入不建任何倒排）。
详见 [库内schema索引声明.md](./库内schema索引声明.md)。

启动日志判断：

- 装配成功：
  ```
  [cjserver] 库内 schema 装配表 'documents': 倒排 4 字段, 组合 2 组, 位图 2 字段, fulltext 0 字段
  ```
- 零索引模式（无 schema 且未给索引声明）：
  ```
  [cjserver] 数据目录无 cj.schema.json 且未声明索引 → 零索引模式（可写 cj.schema.json 声明倒排/组合索引）
  ```
- 倒排存量重建（schema 声明变化时，一次性）：
  ```
  [engine] 倒排声明变更（inv: → inv:channel,city,region,status），全量重建倒排词条（扫 primary）…
  [engine] 倒排重建完成：396117 词条已落段
  ```

## 停止与常见运维

```bash
# 停止（服务常以 root/systemd-run 启动，用 sudo）
sudo pkill -9 -f 'target/release/cjserver'

# 数据目录权限：root 启动过的库，写 cj.schema.json 需属主权限
sudo tee /path/db/cj.schema.json > /dev/null <<'JSON'
{ "tables": [ { "name": "documents", "inverted_fields": ["status"] } ] }
JSON
```

> 连接验证建议用自带 MySQL 协议的工具（rr-conformance / mysql 客户端）；
> 本机 mariadb CLI 连 cjserver 的握手兼容性有限（可能报 `ERROR 2013`），不代表服务不可用。
