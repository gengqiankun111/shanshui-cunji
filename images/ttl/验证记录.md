# 阶段 1.5 · TTL 时间分区 验证记录

> 验证日期：2026-08-27 · M4 里程碑第 3 项（design 5.4，必做）

## 实现

- **按天分桶**：启用 `[storage] ttl_days` 后，flush 时按文档 `ttl_field`（默认 `timestamp`，数值秒级时间戳）提取 UTC 天，
  每个桶写独立 SST：`sst-{days:08}-{id:08}.sst`；无时间字段 / 非 JSON / Tombstone 落入默认桶（无日期前缀，永不过期）。
- **过期整文件删除**：启动时扫描 Manifest，桶天数 < `today - ttl_days` 的 SST 直接物理删除——删除成本 O(1)，**无墓碑**（杜绝旧数据拖垮 Compaction）。
- **WAL 回放过滤**：重启回放 WAL 时同样按 TTL 判断，过期记录不回放入 MemTable（否则过期数据经 WAL 复活）。
- **配置**：`storage.ttl_days`（None=关闭）、`storage.time_bucket`（MVP 仅 `day`，`hour` 预留）、`storage.ttl_field`。
- 日期计算无 chrono 依赖（civil calendar 天数：`epoch_days = secs.div_euclid(86400)`）。

## 验证

### 单元测试（130 全绿，+2 新增）
| 测试 | 覆盖 |
| --- | --- |
| ttl_helpers | 天数计算（含负值 div_euclid）、桶文件名解析（含默认桶/非 SST 文件） |
| ttl_buckets_and_expiry | 4 桶分写（今天/昨天/10 天前/默认）→ 重启：10 天前桶物理删除且不可见、默认桶永不过期 |

### 回归
- demo 冒烟 10/10（默认配置无 TTL → 原 flush 路径不受影响）

## 结论

M4 第 3 项达成：TTL 时间分区（按天分桶 SST + 过期 O(1) 整删 + WAL 回放过滤），删除成本 O(1)、不产生墓碑。
与 PAX v4（SST 版本 4）共存：TTL 桶文件复用同一 v4 写读路径。
