## 测试环境
- 数据库：本机 Windows（SAMSUNG MZVLB512 NVMe），mysql-server（MySQL 协议适配层 v0.7.0）
- 客户端：阿里云 Debian（2 核 1.6GB HDD，106.14.68.116），sysbench 1.0.20
- 链路：本机 3307 ↔ SSH 反向隧道 ↔ 阿里云 127.0.0.1:3306（RTT ~52ms 跨地域）
- 数据模型：scc.documents（LSM 文档库，id 主键 + doc JSON），sysbench sbtest 表 DDL 放行

## Windows 原生压测工具（MSYS2 编译 sysbench + HammerDB 6.0）
2026-08-31 本机 Windows 完成两套压测工具部署（图形/命令行均可演示）：

### MSYS2 编译 sysbench 1.0.20（MINGW64）
- 编译环境：MSYS2 MINGW64（D:\msys64），依赖 mingw-w64-x86_64-libmariadbclient / luajit
- **CK（Concurrency Kit）**：configure 需识别 MINGW64*（352 行 case 修改），`--prefix=D:/msys64/local` 避开 //d 路径坑，头文件手工安装到 D:\msys64\local\include
- **Makefile 适配**（configure 后必打）：
  1. `third_party/concurrency_kit/Makefile`：lib/libck.a 规则改为 `cp D:/msys64/local/lib/libck.a`
  2. 全部 Makefile：CK include 改 `-ID:/msys64/local/include -ID:/msys64/local/include/gcc`
  3. `src/Makefile`：删 `-DDATADIR/-DLIBDIR`（Windows 引号地狱），sb_win.h 提供空默认
  4. `src/Makefile`：`sysbench_LDFLAGS += -Wl,--export-all-symbols`（**关键**：LuaJIT FFI 需要 exe 导出符号）
  5. `third_party/luajit/Makefile`：`BUILDMODE=static`（MINGW 默认不生成 libluajit.a）
- **源码修复**：
  - `sb_win.h`：MINGW32 下清空 MSVC 移植层（改用 winpthreads）+ 补 SIGALRM/alarm/srandom/random shims
  - `sb_util.c`：`buffer`→`buf`（源码 bug）；_WIN32 分支 VirtualAlloc 改 `malloc`（free 兼容）
  - `sb_fileio.c`：_WIN32 下 fstat(HANDLE) 改 GetFileSizeEx
  - `sb_lua.c`：luaL_openlibs 后 `jit.off()`（调试用，可保留）
  - `drv_mysql.c`：use_ssl=false 时 `MYSQL_OPT_SSL_ENFORCE=0` + `SSL_VERIFY_SERVER_CERT=0`（**MariaDB Connector/C 3.4 默认强制 SSL**）
- **数据库侧**：mysql.rs COM_INIT_DB 放宽为接受任意库名（sysbench 默认 sbtest）
- 运行：`sysbench.exe` 需 PATH 含 D:\msys64\mingw64\bin（依赖 libmariadb.dll 等）
- **实测（连本机 3307，db-50m-v070，sbtest1 1000 行）**：
  - `oltp_point_select` prepare：建表 + 1000 行 + 二级索引 OK
  - `oltp_point_select run`（4 线程 10s）：**7064.9 TPS**，avg 0.57ms，95th 0.75ms
  - `threads` 内置测试：129k events/3s，exit 0
