# 阶段 1.5 · Delta CF 部分更新 验证记录

> 验证日期：2026-08-27 · M4 里程碑第 4 项（design 4.7，必做）

## 实现

- **双层结构**：Base CF（全量文档）+ Delta CF（增量字段），Merge-on-Read。
- **Delta 键**：`encode_docid(docid) ++ VarLen(field)`（同 docid 字段聚簇，前缀扫描高效）；值为单字段 JSON。
- **API**：`engine.patch(docid, fields)`（写 Delta）+ `engine.get`（Base + Delta 合并）；`null` 值 = 删除字段；
  HTTP `POST /patch`（`{"docid":N,"fields":{...}}`）+ CLI `patch --id --data`。
- **一致性**：
  - 全量 `put` → `delete_prefix(docid)` 清空该 docid 增量（避免旧 patch 覆盖新数据）；
  - `delete` → 清 Delta + Base Tombstone（Delta 不复活已删文档）；
  - HotCache 写失效 + 合并值回填。
- **收益**：只改单字段时写几十字节 Delta（替代全量 PUT），写入 IO 放大趋近 1（design 4.7）。
- Compaction 压实（老 Delta 并入 Base）留待后续阶段（MVP 保留 Delta，读路径合并）。

## 验证

### 单元测试（133 全绿，+3 新增 + HTTP /patch 端到端）
| 测试 | 覆盖 |
| --- | --- |
| patch_merge_on_read | 覆盖/新增/null 删除字段、未 patch 字段保留、重启（WAL 恢复）后 Delta 仍生效 |
| full_put_clears_delta | 全量 put 覆盖后旧 Delta 清空，不污染新数据 |
| delete_clears_delta | 删除后 Delta 不复活文档 |
| http_end_to_end（扩展） | POST /patch → get 返回覆盖 + 新增字段、旧值不残留 |

### CLI 端到端
```
put 1001 {"status":"active","amount":100,"device":"android","docid":1001}
patch --data '{"status":"inactive","amount":null}'
get 1001 → {"status":"inactive","device":"android","docid":1001}   # status 覆盖、amount 删除、device 保留
```

## 结论

M4 第 4 项达成：Delta CF 部分更新（双层 Merge-on-Read + null 删除字段 + 全量覆盖/删除的一致性清理），
写入 IO 放大趋近 1；复用 v4 SST 读写路径，与 PAX/TTL 共存。
